# 内置搜索多工具挂载

让 AstrBot 在同一次 LLM 请求中同时提供多个框架内置搜索工具，补充框架“网页搜索提供商”单选项的能力。

插件动态读取框架内置工具注册表，用框架的搜索配置条件识别搜索及网页提取工具。工具名称和说明自动成为插件设置页的多选项，插件中不维护引擎名称、工具类或 API Key 字段的名单。

工具实例、API 请求、Key 轮询、错误处理及返回格式都直接使用 AstrBot 已有实现；Key 等设置仍读取当前聊天实际绑定的框架配置文件。

## 安装

在 AstrBot 插件管理中通过以下仓库地址安装：

```text
https://github.com/monbed/astrbot_plugin_builtin_search_mount
```

在 AstrBot 插件管理中使用“从文件安装”，选择 `astrbot_plugin_builtin_search_mount.zip`。

也可以将整个 `astrbot_plugin_builtin_search_mount` 目录放入 AstrBot 的 `data/plugins/`，然后重启 AstrBot。

当前实现最低要求 AstrBot `4.28.0`：插件读取该版本引入的 `agent_runner.runner_type` 配置结构，并使用框架的内置工具注册表接口。版本下限按接口依赖确定，不随框架发布新版本而上调。不包含旧版接口兼容分支，也不需要额外依赖。

已分别使用 AstrBot `4.28.0` 和标注 `4.29.3` 的框架源码完成 14 项隔离测试。配置结构变更见 [4.28.0 发布说明](https://github.com/AstrBotDevs/AstrBot/blob/v4.28.0/changelogs/v4.28.0.md)。

## 配置步骤

1. 在聊天实际使用的框架配置文件中开启 AI，执行方式选择“AstrBot 内置 AI”。
2. 在 `AI → 能力 → 网页搜索` 中开启“启用网页搜索”，原来的提供商单选项继续保留一个常用引擎。
3. 将需要使用的其他引擎的 Key 也保存到同一份框架配置文件中。可以临时切换提供商填写、保存各家的 Key，再切回常用引擎；也可以直接编辑框架配置 JSON。
4. 打开本插件设置，在“同时挂载的内置搜索工具”中多选所需工具，保存设置。选项和说明由框架注册表动态生成。
5. 向模型明确要求调用对应引擎，例如：“分别使用 Tavily 和 Exa 搜索这个问题，再交叉核对结果。”

### 同时使用 Tavily 与 Exa

将以下字段合并到原有框架配置的 `provider_settings` 中，保留其他已有字段：

```json
{
  "web_search": true,
  "websearch_provider": "tavily",
  "websearch_tavily_key": ["你的 Tavily Key"],
  "websearch_exa_key": ["你的 Exa Key"]
}
```

在插件设置中勾选：

```json
{
  "tools": ["web_search_tavily", "web_search_exa"]
}
```

如还需要按 URL 获取正文，可另外勾选 `tavily_extract_web_page` 和 `exa_get_contents`。

插件不会根据已保存的 Key 自动挂载其他引擎，也不会自动补选正文提取工具；框架原来加载的工具会继续保留。如果希望使用两家引擎，把框架单选提供商设为这两家之一即可。

## 框架新增工具后

框架升级并重启后，重新打开插件设置，新注册的搜索工具会自动出现在列表中。新工具默认不勾选，由你决定是否挂载，已有选择继续保留。

插件启动时和每次处理 LLM 请求时都会重新读取注册表并刷新内存中的配置选项。运行中注册的新搜索工具也会在下一次请求后出现在重新打开的设置页中。框架删除的工具会从选项中消失，配置里残留的旧名称会被跳过。

自动发现使用框架当前的注册约定：内置工具通过注册表注册，并声明依赖 `provider_settings.web_search`。框架沿用该约定新增搜索引擎或正文提取工具时，无需修改插件；若将来改变注册接口或分类约定，则仍需适配。

## 运行行为

- 插件在 `on_llm_request` 中调用框架的 `get_builtin_tool(name)`，将返回的原生实例加入当前请求的 `ToolSet`。
- 插件配置默认空列表，安装后需要手动勾选工具。
- 遵守当前会话框架配置的网页搜索总开关，关闭后不补挂载；仅作用于 AstrBot 内置 AI 执行方式。
- 同名工具已经存在时保留原实例；不改写工具名称、Schema、描述或 `active` 状态。
- API Key 缺失、无效或额度不足时，直接由对应内置工具返回原有错误。
- 插件选择的是补挂载范围，不会删除框架或其他插件已经加入的工具。已生成的请求不会因后续修改配置而被回写。
- 同时挂载表示模型可以使用这些工具，是否调用以及调用次数仍由模型决定。

框架的提供商下拉框仍然是单选，内置工具页的启用标签也按原框架单选配置计算；补挂载的工具以实际请求中的工具池和调用记录为准。
